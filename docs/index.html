3. Năm đặc tính điện toán đám mây theo NIST

Đặc tính NIST Thao tác thực hành và minh chứng
1. Tự phục vụ theo yêu cầu (On-demand Self-service) Tự chọn Use this template, tạo repository mới và nhấn Create codespace on main để cấp phát môi trường lập trình mà không cần nhân viên nhà cung cấp cài đặt thủ công.
2. Truy cập mạng rộng (Broad Network Access) Mở API qua trình duyệt máy tính và điện thoại bằng URL GitHub Codespaces sau khi chuyển cổng 3000 sang Public. Sau khi thử nghiệm, chuyển lại Private.
3. Gộp tài nguyên (Resource Pooling) Sử dụng CPU, RAM và môi trường máy ảo do GitHub cung cấp. Người dùng không cần biết hoặc tự quản lý máy chủ vật lý cụ thể đang chạy ứng dụng. Trường host cho biết tên máy chủ của môi trường hiện tại.
4. Co giãn nhanh (Rapid Elasticity) Có thể nhanh chóng tạo, khởi chạy và dừng Codespace khi nhu cầu sử dụng thay đổi. Bài thực hành minh họa việc cấp phát và giải phóng môi trường; chưa thực hiện kiểm thử tự động co giãn tài nguyên theo tải thực tế.
5. Dịch vụ đo lường được (Measured Service) Theo dõi mức sử dụng Codespaces trên Billing & Licensing → Usage, bao gồm thời gian sử dụng compute (core-hours) và lưu trữ (GB-hours).

4. Kết quả triển khai API Hello Cloud

Ứng dụng được viết bằng Node.js và Express, sử dụng hai tệp app.js và server.js để tách biệt phần xử lý ứng dụng với phần khởi chạy máy chủ.

API GET / trả về thông điệp chào mừng cùng các thông tin về máy chủ như hostname, hệ điều hành, CPU, RAM, thời gian hoạt động và thời điểm phản hồi.

API kiểm tra: GET /
Cổng chạy: 3000
Kết quả: Trả về dữ liệu JSON.

5. Kết luận

Qua bài thực hành, em đã tạo được một môi trường lập trình trên GitHub Codespaces, khởi tạo dự án Node.js, triển khai API Hello Cloud và truy cập API từ thiết bị khác thông qua cổng được chuyển tiếp.

So với môi trường cài đặt trên máy cá nhân, Codespaces giúp giảm công sức chuẩn bị môi trường, thuận tiện chia sẻ và truy cập từ nhiều thiết bị. Các thao tác tạo, chạy, dừng và theo dõi mức sử dụng giúp nhận diện năm đặc tính của điện toán đám mây theo NIST.
